Frequently asked questions

Common questions before and after purchase.

Does this module work on Odoo 17 or 18?
No. This module is built specifically for Odoo 19 Enterprise and uses several Odoo 19-only APIs (the renamed hr.version model, the new sex field on employees, the 1_new/2_pending/3_done appraisal state codes, OWL 3 components). It will not install on earlier versions.
What if I don't have Payroll or Appraisal installed?
The module installs and runs fine with just the four core dependencies (hr, hr_attendance, hr_holidays, hr_expense). The Payslips KPI cards and Appraisals section automatically hide when those modules aren't present — no errors, no broken charts. Install them later and the dashboard picks them up automatically.
Can I customize the colors without editing code?
Yes — that's the whole point of the theme system. Open HR Dashboard → Configuration → Dashboard Theme and you'll find 17 editable fields: primary/secondary/accent colors, three background gradient stops, six card category colors, text colors, glass opacity, blur intensity, and border radius. Changes save instantly and apply on the next dashboard reload. No module upgrade or server restart needed.
How do I activate the Arabic translation?
Three steps:

1. Go to Settings → Translations → Activate Languages and enable Arabic.
2. Upgrade the module: ./odoo-bin -u msn_hr_dashboard.
3. In your user preferences, switch your language to Arabic and refresh.

The dashboard renders in RTL with all 158 strings translated.
Can I add another language (French, Spanish, German, etc.)?
Yes. Copy i18n/ar_001.po as a template, rename it to your language code (e.g. fr_FR.po), fill in the msgstr values, then upgrade the module. Odoo auto-discovers .po files in the i18n/ folder.
Are approvals secured? Can any user approve anything?
No — the dashboard respects standard Odoo HR access groups. Approval actions execute as the real user, not via sudo(). A user who can't approve time-off requests in the standard Time Off app also can't approve them in the dashboard — they'll see an inline access error notification. No privilege escalation, no security shortcuts.
What happens when I click a KPI card?
The dashboard opens the underlying record list, pre-filtered to match the KPI. For example, clicking "Pending Leaves" opens the Time Off list filtered to records in confirm or validate1 state. The Create button is hidden by default to keep the dashboard's read-focused workflow intact.
Does the Department bar chart click do anything?
Yes — clicking any bar in the "Employees by Department" chart opens the employees of that department in a list view. Same drill-through pattern as the KPI cards.
Will the charts work offline / in air-gapped deployments?
Yes. Chart.js 4.4 is bundled inside the module (static/lib/chart.umd.min.js). The dashboard makes zero external CDN requests for fonts, libraries, or assets. Works behind firewalls, in self-hosted deployments, and on isolated networks.
Can I install on multiple Odoo databases?
One purchase covers unlimited installations on a single Odoo database instance. If you operate multiple separate Odoo databases (different customer environments), each needs its own license. This is the standard Odoo Apps Store policy for paid modules under OPL-1.
Is the source code included? Can I modify it?
Yes — the module ships with full readable source code (Python backend, OWL JS/XML frontend, SCSS theme, no minification). You may modify it for use in your own Odoo deployment. What's not allowed under OPL-1 is redistribution: you can't resell or repackage the module. See the LICENSE file for full terms.
How long is support included?
Email support for installation and configuration questions is included with your purchase. All future 19.0.x patches and improvements are also included at no additional cost. If a future Odoo 20 version requires a major rewrite, that would be a separate upgrade purchase.

  3. A clear description of what you expected vs. what happened
  4. Any error messages from the browser console (F12 → Console tab)
  5. Relevant Odoo server log entries if the issue is server-side
